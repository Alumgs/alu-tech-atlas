# 4.5 interaction changes

News feeds and the highlights list share one clustering pass. A clustering call computes title normalization, numeric tokens, parsed dates, canonical URLs, scores and comparison grams once per item. The grouping criteria and evidence records are unchanged. A synthetic Node comparison over the same 600 inputs produced equal full grouping output and a five-run mean of 89.2 ms before and 30.1 ms after; this is an algorithm benchmark, not a browser navigation metric.

Each visited news scope retains its list state. Hidden scopes keep their last visible inputs and skip feed updates. View changes run in a React transition, cached news is reused, and search text is deferred. Reports are clustered when entering research or exporting rather than on every unrelated page. Feed paints are batched at 1.5 seconds, with immediate initial and final results. Internal handbook and case links use framework navigation without speculative mass prefetching.

Translation results use a per-provider keyed external store. A result notifies only that text's subscribers. Requests coalesce in batches of four, duplicate in-flight text is suppressed, departed queued texts are dropped and navigation cancels pending translation work while preserving completed translations. Turning translation off aborts work and displays originals. No translation response updates the entire portal context.

Settings open in a dialog. Device reading preferences persist under a versioned browser key: automatic translation/refresh, palette, density, type size/font, content width, summaries, highlights and reduced motion. They apply immediately without shared-site mutations. Existing site/admin controls remain behind administrator password confirmation; successful saves update the current portal immediately. Site translation permission is separate from summary enrichment, with the prior disabled state preserved when migrating old configuration. The legacy settings route redirects to the portal dialog.

Source selection uses a searchable popover with a draft, all/none, cancel/apply, counts and unavailable states. Multiple selected feeds are combined with OR. Null means all sources; an empty selection means none. Applying a filter does not remount the feed. Source popovers close when their retained scope becomes hidden. Directory IDs are scoped to prevent anchors targeting hidden streams.

Validation includes preference sanitization, independent site flags, multi-source semantics, keyed translation notifications, cache reuse, in-flight deduplication, abort/retry and bounded batching, existing grouping tests, type checks, builds and authenticated production smoke checks. The original 4.5 source validation did not measure browser latency. Local preview remains blocked by credentials for the existing remote AI binding. Authenticated production Chromium regression now runs in CI with the existing credential confined to that process. It checks live-report multi-selection, settings controls, desktop/mobile layout, retained views and document reloads, and logs warm navigation commit-plus-two-frame timings. It uses an isolated device preference profile with automatic translation and background refresh off, plus actual reports from four production feed responses. These CI timings do not represent every user device, cold loading or completion of external source checks. No browser session, password trace or screenshot is saved.

The 4.5.1 browser follow-up covers directory scrolling before opening the picker. Source popovers track trigger movement while open and use the available viewport height, with only the source list scrolling; controls remain accessible after scrolling through a long page. It also checks client navigation into an article and back.

## 4.5.2 settings follow-up

Removed the flashing navigation progress strip; transitions retain their accessible busy state. Reading preferences, website configuration and account controls now share one scrollable dialog without tabs. The portal supplies its settings snapshot to the dialog instead of each opening triggering a second request. Initial cloud reads have a ten-second deadline and an explicit retry state; device controls stay usable throughout, while unloaded defaults cannot be saved over an existing configuration. Website and editorial fields share one save action with adjacent password confirmation. Clicking save without a password focuses the field and explains the requirement instead of silently disabling the button. Save requests time out after fifteen seconds and re-enable after errors. Browser coverage includes these cases with intercepted save responses so shared cloud configuration is not modified.
